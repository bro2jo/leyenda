# /ingest

1. Read the whole document first. Decide what it is:
   - **A PT or surgeon visit note** (written or as he reports it): `real/visits/YYYY-MM-DD_PTn.md` (or `_surgeon.md`) with the headings Measured · Session · Instructions · Questions · Next morning; every measured number also goes to `real/logs/measurements.csv` (`python3 engine/darrow.py measure add '[…]'`, one row per side, `visit` = the file's stem); exercise rows to the exercise log with `session=PT`; `daily_log` gets `pt=Y` and a one-line `notes` pointer to the file. Then NOW's top: the questions it answered (State §5 keeps the list; NOW names which are now answered and any new ones), the gate, and "PT n outranks the State until the dashboard's next State folds it in". The words also belong in the dashboard's `ACL_PT_Notes.md`: remind him once to paste the note there; never edit `real/visits/ACL_PT_Notes.md` here.
   - **The dashboard's files** (his ACL dashboard project; `real/plan/ACL_Project_Index.md` lists them and where each fact lives) are taken **as uploaded**, whole, never rewritten here. Before replacing one, diff it against the file in place and name in the reply anything the old one held that the new one no longer does (a rule, a dose, a fact) and where it went (the index's "Audit" section usually says); anything that went nowhere is asked about, not dropped silently. **One standing addition** (his call, 10/12): the throwing plan is named in the index (file 9, where throwing lives, reading order), the Working Rules (priority; a Program structure bullet), the Add-On (the Sport line) and the State (§1 Sport; the week's throwing days in §6). An upload that lacks those lines gets them back, and a fact he has confirmed against it here (Sat 10/10 had a heel prop) is corrected in it; the reply says so, so he can carry the same lines into the dashboard. An upload with a different name (`… (2).md`) takes the canonical name. Uploads that land at the repo root or in `real/` are moved into place and their stray copies deleted.
     - **Authority** (master plan, Working Rules, Add-On, `24-week-offseason-program-v4.md`, the project index): replaces its file in `real/plan/` (a new authority keeps its original filename and gets `##` headings for its numbered sections, wording unchanged, plus a `doc` name in `engine/darrow.py` if it will be read often). The master plan and the off-season program are never edited, so a new copy should differ only in whitespace: say so if it doesn't. A changed rule or section number is followed through `CLAUDE.md`, the skills, `real/config.json` (`weekly_template`, `optional_from`, `daily_minimum`, `conditioning`) and `engine/rules.json`.
     - **The Recovery State** (`ACL_Recovery_State_<Sunday>.md`, ten sections): replaces the one file in `real/state/` (a revision under the same Sunday's name in place; a new Sunday's moves the old one to `real/state/archive/`). Then reconcile: every clinic number in §4 is in `measurements.csv` (add what's missing); §5's next-visit list replaces NOW's (NOW keeps only what came in after the State); §6–7 (this week's days, upper placement, unlocks) → `real/config.json` (`weekly_template_history` for this week, `plan_changes`, `optional_from`) so `today` and `week` show the same plan; anything this repo logged that the State doesn't know (a visit, a trainer's instruction, the sport plan's throwing) stays in NOW's top and is named in the reply.
     - **`ACL_PT_Notes.md`**: replaces `real/visits/ACL_PT_Notes.md`. A new entry's numbers go to `measurements.csv` and its exercises to the exercise log (`session=PT`) if they aren't there yet; the words stay in the notes (no separate visit file for an entry the notes already hold).
   - **Log** (e.g., `ACL_Daily_Log.csv`, an older nutrition log): merge into the matching file in `real/logs/` by date. Map columns to the current schema, never duplicate a date, and fill only blank fields; where the upload contradicts what the repo logged from his own message (a day it calls empty that has a heel prop here), the repo's record stands and the reply names the difference. A file in another schema (the dashboard's `ACL_Daily_Log.csv`) replaces its verbatim copy in `real/logs/archive/` (column map: `real/logs/archive/README.md`, updated for any new column, which also gets a `daily_log.csv` column in `engine/darrow.py → COLS`); its long notes stay there, not in a cell. `ACL_Exercise_Log.csv` shares the schema: the upload's rows replace the repo's for the dates where they differ (check every earlier date is identical first, and that no date logged here is missing from the upload). A correction that changes a loaded day, floor or check is named in the commit and the reply, with its Reckoning change. Run `python3 engine/darrow.py check`, then `sync`.
   - **Nutrition project instructions:** save to `real/plan/nutrition_instructions.md` and adopt its food-line and recap formats in `.claude/skills/log/SKILL.md` and `CLAUDE.md` ("Reply shape for a log"), keeping the Ledger-then-Chronicle structure.
   - **Sport material:** hand over to `/sport`.
2. Update what it changes, citing the document in each `source`/`evidence` field:
   - `real/config.json`: nutrition targets, `weekly_template`, `rehab.current_phase`, `next_gate`, `knot_gates`, milestones.
   - `CLAUDE.md` → Golden rule 1's source-priority list, if it's a new authority.
   - the top section of `real/NOW.md` (plan in force, next PT visit and its questions, the gate, flags).
3. Contradictions: if it conflicts with something already here (dates, doses, targets), the source priority in CLAUDE.md decides. Say plainly what changed and what you couldn't reconcile, and ask one question if needed.
4. Never touch the story here. If it ties a Knot (a gate passed with PT/surgeon clearance or measured criteria), record it with `python3 engine/darrow.py knot tie …`, then `python3 engine/saga.py now`: its KNOT line says when the Book's transition falls due. Only when it says **at this chapter's climax** are the week's remaining `planned` slots re-planned toward the crossing (`python3 engine/saga.py plan slot N key=value …`: plan, kind, beat or quest+stage, micro as JSON; then `python3 engine/saga.py check`); when it says the transition waits some chapters, this week's plan stands and the next checkpoint plans the crossing chapter by the arc's compress rule.
5. `python3 engine/darrow.py sync`, then commit and push: `git add -A && git commit -m "ingest: <file>" && git push origin HEAD:main`.
6. Reply: what the document is, what it changed (targets, schedule, gates), and anything still open. Real only.
